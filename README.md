# URLColors

Chrome Extension to highlight the body of a webpage with colored border for URL's that match user settings.

This extension allows you to flag specified websites by highlighting the website with a colored border. This is especially useful for developers who run their web applications on many different environments and who are constantly switching between a dev, test, and production version of an app or database. Because the application may look the same on all environments, it's easy to accidentally do something on the production environment that shouldn't have been done.

With URLColors, you can easily have the browser flag important websites for you by specifying the keyword to match against the tab url, the border color, width, whether or not the border should blink, and the interval of blinking.

Website: www.urlcolors.com

Chrome web store: https://chromewebstore.google.com/detail/urlcolors/jjccpcminoppplpmcfghflolejbdkekm?utm_source=github&utm_medium=readme

Trusted by 9,000+ users.

## Other browsers

The source at the repo root (`manifest.json` + the `urlColors*.js`/`.html` files) is the Chrome build and needs no
extra steps. The other targets read from the same source files, packaged differently per browser.

### Firefox

Firefox's Manifest V3 needs `background.scripts` instead of Chrome's `background.service_worker`, and a
[`browser_specific_settings.gecko.id`](https://extensionworkshop.com/documentation/develop/extensions-and-the-add-on-id/)
to publish, so Firefox gets its own manifest, `manifest.firefox.json`. Everything else in it is kept identical to
`manifest.json` on purpose — `npm run check:manifests` fails if they drift apart on any key other than those two.

```bash
npm run build:firefox   # assembles dist/firefox/ (gitignored) from the shared source + manifest.firefox.json
```

To test: `about:debugging#/runtime/this-firefox` → **Load Temporary Add-on** → pick `dist/firefox/manifest.json`.

**Before submitting a new version to AMO**, replace the placeholder in `manifest.firefox.json`'s `gecko.id` with
this project's _existing_ add-on ID (find it in the [AMO developer hub](https://addons.mozilla.org/developers/) for
the current [URLColors listing](https://addons.mozilla.org/en-US/firefox/addon/url-colors/)) — uploading with the
wrong ID creates a separate add-on rather than updating the existing one, orphaning its current users.

### Safari

`safari/URLColors/URLColors.xcodeproj` is a macOS Safari Web Extension wrapper, generated by Apple's own
`safari-web-extension-converter` and then customized. Its extension target holds its own copies of the shared
source files (the converter has no notion of a shared source tree), so after editing any of them, copy the updated
file(s) into `safari/URLColors/URLColors Extension/Resources/` and run:

```bash
npm run check:safari   # fails if those copies no longer match the repo root
```

**To test locally** (no paid account needed): open the project in Xcode, select the **URLColors** scheme, and Run.
The wrapper app that launches explains how to enable the extension — you'll need to turn on "Allow Unsigned
Extensions" in Safari's Developer settings first, since this isn't signed with a real team yet.

**To publish to the App Store**: requires enrolling in the
[Apple Developer Program](https://developer.apple.com/programs/) (paid, identity-verified — only the account owner
can do this), then setting that team in the project's Signing & Capabilities before archiving and distributing
through Xcode Organizer.

### Chromium-based browsers (Edge, Brave, Opera, Vivaldi, …)

These already load the Chrome build as-is; no changes needed. Edge has its own store
([Partner Center](https://partner.microsoft.com/dashboard/microsoftedge/overview)) if a separate listing there is
wanted for discoverability — same package, no code changes.
